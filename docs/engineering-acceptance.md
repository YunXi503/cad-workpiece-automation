# 工程貼面草稿的交付判準

**目標是減少工程師手動工作與時間，快速生成貼近主要工件外形、略過難加工焊道起伏、方便局部微調的貼面草稿。** 精度提供偏差位置與修正依據，不以固定 0.3 mm 決定整個專案成敗。

## 決策與適用範圍

2026-11-06 使用者再次明確說明上述優先順序，延續 2026-10-23「允許近似與幾何推估、先交可微調線弧／貼面、減少工程師工時」的工程草稿目標。先前文件把嚴格接觸診斷提升成整體交付門檻，未充分反映這個用途，本次更正。

這是**交付目標的調整紀錄**。既有原始資料、曲線、測試門檻及失敗結果均保留；沒有將舊數字改成通過，亦未據此宣稱已完成製造驗收。實際加工若另有關鍵尺寸或配合要求，應在對應部位另行確認。

## 主要看四件事

| 工程交付判準 | 如何判讀／記錄 | 目前證據 |
| --- | --- | --- |
| **少做手動建模** | 能否自動建立側線、約束草圖與面；工程師剩下哪些設定、確認及修改 | 已在 VSTA 實跑 3 草圖、165 線弧、405 有效約束、3 有限延伸特徵。支持域與部分範圍仍由既有資料／人工審查提供。 |
| **主要外形可用，焊道細節可簡化** | 主要分支、肩部、端部範圍是否合適；是否避開不需要追隨的焊道凸起、局部折皺和密集小段 | [原件／貼面疊合](surface-contact.md)與[剖框](original-case.md)可審看；尚未有涵蓋全部焊道區域的工程確認。 |
| **剩餘微調少，能接續操作** | 記錄需要改的區域、元件、操作與時間；是否需要整段重畫；能否完成手調後建面 | 草圖原生可編輯。公開的嚴格計畫流程尚缺手調後新幾何匯出／重新驗證；此操作缺口仍需處理。 |
| **從開始到可用草稿更快** | 同一輸入與同一可用草稿標準，比較現行人工方法與輔助流程的總時間、人工投入及失敗重做 | 尚未完成同條件工時對照，不能填節省百分比。 |

沒有在本次指定「節省幾成」「最多修幾段」等數字；未由工程用途決定的門檻不自行補上。已自動生成多少 CAD 幾何是實測事實，但不能直接換算成節省多少分鐘。

操作端已補 [WinForms 生成／核對／審閱](operator-guide.md)，沿用同一幾何核心；自動耗時保存在本機輸出。這改善了執行入口，沒有把離線計算時間當作 CAD 人工工時，也沒有據此宣稱原生手調後的驗證接續已完成。

工程師可以先依實際操作、主要外形及剩餘修改接受草稿，不必等完整計時研究才交付。若要在履歷寫節省時間或百分比，再以對照紀錄支持；不把新的量測表變成另一道僵硬門檻。

## 精簡程度與誤差的工程取捨

原件已有兩種已記錄草稿：

| 版本 | 線弧元件 | 相對同一草稿的 XY 診斷（mm） | 現在如何解讀 |
| --- | ---: | --- | --- |
| 歷史工程版本 | 129 | 0.255364／0.340447／0.495341，取整前 | 部分側別高於舊 0.3 目標，仍可作較少元件的工程候選。 |
| 本次公開重實作 | 165 | 0.296583／0.294134／0.258049，取整前 | 三側均在本版擬合目標內，元件較多；另有取整後驗證。 |

兩版來源、演算法及原生證據各自保存。不能只因 129 較少就判定省時，也不能只因 165 的兩側誤差較小就判定更適合工程交付。應實際看細碎轉折、焊道避讓、需要修改的位置及工作量；沒有為這個新工程比較填造勝負。幾何技術的價值也包括知道何時保留細節、何時用少量可編輯元件表達主要輪廓。

## 去焊道在這個流程中的意思

保留原掃描作來源證據；**生成的工程面以主要輪廓為目標，不必逐一複製使加工困難的焊道凸起與細碎轉折**。這是衍生草稿的簡化用途，沒有修改或抹除原 STL。

局部避開焊道後，對原焊道點的距離可能增加，因此「到所有原掃描點更近」不能單獨代表更好的工程草稿。仍需確認主要輪廓、肩部及端部沒有被錯誤削去、跨到其他分支，並將工程師接受／需修的區域標出。現有來源防護與線弧簡化提供基礎，尚未宣稱全自動辨識並移除所有焊道。

## 精度與結構分開看

| 項目 | 在目前交付中的角色 |
| --- | --- |
| 原支持點到面的距離、0.3 mm 參考線 | 診斷偏差與引導工程審看。超過參考線不自動否定整份可微調草稿，也不自動代表焊道已被正確避開。 |
| 現行擬合 XY 0.3 mm、取整位移 0.05 mm | 本版演算法與回歸已使用的設定，本次不改程式；不是對所有後續工程情境宣告不可變的公差。 |
| 有限線弧、合理方向、接點與 G1、約束有效 | 讓草圖／面可生成、可編輯、可預測的幾何結構檢查；精度次要不表示允許斷裂、反向弧或壞模型。 |
| 來源指紋、正確 Part／草圖身分、原生讀回 | 確認程式處理的是預期幾何。讀回殘差描述轉接一致性，不是加工精度或省時證明。 |
| 舊收據 `physicalContactAccepted: false` | 保留原接觸試驗狀態；不是新版「減少人工工作的草稿交付」總結論。 |

## 工時與手動工作的對照紀錄

先選同一工件、範圍、起始資料與可用草稿標準。人工組採工程師平常的方法，不刻意要求最慢的逐段描線；輔助組必須計入其實際需要的支持準備、設定、審看、修正、失敗與重做。若支持資料事先整理，這筆人工成本要明列，不能隱藏在計時之外。

| 記錄欄位 | 現行人工流程 | C#／VSTA 輔助流程 |
| --- | --- | --- |
| 起始資料與處理範圍 | 待同條件記錄 | 待同條件記錄 |
| 人工操作時間 | 未量測 | 未量測 |
| 開始至工程師接受草稿的總經過時間 | 未量測 | 未量測 |
| 設定、審看、手調與重做內容 | 未量測 | 未量測 |
| 焊道困難區域的處理結果 | 待工程確認 | 待工程確認 |
| 最終接受／需再修的部位及理由 | 待記錄 | 待記錄 |

人工投入與總經過時間分開記錄，避免把無人值守的程式等待全算成人工，也避免忽略整體交付延遲。有同條件實測後，再計算人工工時減少率 `(人工流程投入 − 輔助流程投入) / 人工流程投入`，同時報告剩餘修改和失敗案例。

## 目前可以怎麼描述成果

**已實證**：以 C# 幾何與 CATIA VSTA，從既有支持資料自動生成可編輯線弧、約束及三側貼面草稿；幾何和原生讀回可追溯。

**交付目的與待補證據**：減少手工描線、約束和建面操作，避開難加工焊道細節，讓工程師集中處理局部微調。全區焊道效果、剩餘手調量及「大幅省時」尚需工程確認／同條件量測，不以接觸距離或元件數代替。
