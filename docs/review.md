# 作品集審查與修正

這份紀錄是執行者依面試官與首次讀者視角做的自評。每項評為 0 未達、1 需額外推敲、2 可獨立核對。結束條件為連續兩輪各視角至少 9 分、每項至少 1 分，且交付內容沒有未處理的重現阻塞、錯誤主張或公開資料問題。

## 初版走讀後的修正

| 找到的問題 | 修正與查核 |
| --- | --- |
| 面試官只能看到流程，難以由舊方案直接走到實作 | 每個方法增加固定命令、原理、反例、歷史狀態及原始碼行號。補入早期點雲、區間包絡、中心線和弧長等分。CLI 單獨重跑 25 個案例，並與全量結果核對。 |
| 讀者遇錯時看到過長例外，Windows 開檔入口與繪圖未覆蓋 | 將可預期的資料錯誤轉為明確拒絕訊息，指定 STA 入口，建置並驗證開啟報告、切側與視窗繪圖。 |
| 很小的原始點誤差顯示為零，缺口圖容易被誤認為正常 | 報告及圖面標出原始、等分與取整誤差的不同用途。WinForms 站位覆蓋以紅色標未定，缺口反例證明第二側確實被保留為未定。 |
| 只寫一列「CAD 成功」容易混淆外部 STA、VSTA 編輯器與實物結果 | 分開刊載原生執行入口、草圖讀回、四個原生拒絕控制、VSTA 宿主待測及實際工件貼合狀態。 |

## 追加正確性複查

初版的走讀分數是執行者自評。後續以竄改報告及錯誤輸入測出，舊版會接受重複來源三角面，亦會接受三份報告一致、但原始掃描沒有該缺口的結果。將導引清單設為空值會造成未處理例外。

修訂版從原始掃描重播站位、來源清單與扣留結果，並保留獨立的幾何數值檢查。重複來源、偽造缺口、無故扣留和空值輸入都有回歸控制。README 首段直接說明讀者得到的 CAD 草圖，快速開始補上 SDK 檢查、預期成功訊息和圖例。 [驗收與證據](verification.md)

## 接手與交付複查

用同一份正常合成計畫，比較舊版與新版的交付行為。舊版可在預覽被替換時回報通過，也可在 CATIA 草圖新增一條計畫外實線時建立 3 個延伸面。新版預覽會從驗證資料重製核對，替換及移除都會被拒絕。原生對照拒絕計畫外實線與被改為施工線的必要曲線，保留輔助施工線的正常建面路徑。

新增接手頁，將常見故障連到實際的欄位、程式和重跑步驟。 [接手工程師的五分鐘檢查](handoff.md) · [驗收與證據](verification.md)

## VSTA 編輯器及 Linux 複查

實跑辨識出三個宿主差異。F5 使用啟始專案，從磁碟重載來源後仍須在 IDE 儲存以更新巨集，宿主的內建編譯器要求較舊的 C# 語法。將公開 Macro 原始碼調為 C# 5 相容，直接編入新庫並使用同一份合成計畫後，F5 完成 CATIA 草圖、讀回和建面。Debian 虛擬機也從來源完成 CLI 建置和完整回歸。 [重跑 VSTA](macro.md) · [驗收與證據](verification.md)

## 整件案例複查

- **面試官路徑**由首頁整件網格進 B29，沿剖框回查兩個連通分量，再讀歷史混蓋的重複來源反例。把兩種機制和各自的決策分開，保留已實跑的 `normal` VSTA 收據入口。 [逐站追查](workpiece-case.md#逐站追查)
- **首次讀者路徑**由整件 `workpiece` 生成 STL、驗證 A/C 交付及 B 側扣留，再讀 C09 的推估前後狀態。另用 `workpiece-height` 核對兩案 STL、ASC 和 XY 曲線一致，三維樣點距離隨高度下界變動。Windows 檢視器實際繪出整件報告的 B 側。 [高度對照](workpiece-case.md#高度單變數對照)

## 懸吊臂主案例複查

- **面試官路徑**從上下殼、焊道與套筒的整體圖進入原剖框，再追到蓋支持跨度、同蓋推估、雙轉折線弧、取整閉合及 VSTA 原生收據。基準段數採用實際局部擬合串接的 6 段，顯示共線合併後的 5 段。兩種外形的來源、數據與原生結果各自綁定。 [工程案例](suspension-arm.md)
- **首次讀者路徑**由首頁命令重跑 `arm`，`section` 顯示推估前的套筒未定，`run.json` 顯示衍生草稿。另從反例入口重跑 `arm-switch`，可看到兩側被扣留，從 `arm-height` 可看到 XY 通過而三維接觸超差。產生器的設計標籤檔在回歸求解前刪除。 [回歸入口](../tests/arm_acceptance.py)
