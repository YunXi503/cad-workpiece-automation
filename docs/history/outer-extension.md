# 外緣局部補線

**歷史狀態**　待驗證

## 問題

有些框的原串分離，局部延伸可能協助找到真正的側壁支持。

## 程式與合成對照

合成測試同方向、同支且共線的兩段只提供局部接續候選。不同支即使共線也拒絕。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run outer-extension
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L180)

## 後續去向

原專案曾有人工確認的代表框，其餘候選需逐框複核。延伸線與虛交點保留衍生身分。


## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 缺掃端部可由局部趨勢產生有限工程延長候選。 |
| 反例暴露什麼 | 外推不能冒充原始交線，套筒排除域也不能被延長補回。 |
| 後續怎麼處理 | 正式採用的完整範圍未確認；現行只在已授權草稿與有界參考域使用推估。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 2026-11-08 公開最小重現的實測

**本反例判準**：同分支共線可提候選，換分支必須拒絕。

| 輸出欄位 | 本次值 |
| --- | --- |
| `sameBranchProposal` | `True` |
| `crossBranchProposal` | `False` |
| `role` | `inferred bridge` |

相容時只得到推估補接提案；正式採用範圍仍未確認，不能補回已排除套筒。

本輪 `reproduced=true`，表示自製例的預期現象重現；不改變頁首歷史採用狀態，也不等於原公司程式已完整重寫。數值表顯示6位有效數字，完整輸出與數值來源版本見[25方法實跑收據](../evidence/history-replay-20261108.json)；無私有工件輸入。

## 現行工程草稿中的角色

有界推估可減少缺掃區手工補接；原缺口保持、衍生段另列。套筒等已排除範圍不被補回，避免用補線造成新的加工／修形負擔。 [現行交付判準](../engineering-acceptance.md)。
