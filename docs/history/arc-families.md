# 單、雙、三弧相切模型

**歷史狀態**　僅供診斷

## 問題

單圓描述不足時，試更多連續弧來分離蓋、過渡與壁。

## 程式與合成對照

用共同切向構造一、二、三弧鏈，再以同一端點檢查單弧距離與多弧接點切向。合成程式是已知正例產生器。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run arc-families
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L83)

## 哪些證據足夠，哪些還不夠

單弧自由度不足時，雙／三弧可讓蓋側、過渡與壁側使用不同曲率；共同接點及切向限制才使它們成為 G1 鏈。公開正例從共同切向建幾何，再量端點與切向差，足以證明這一組模型存在。

但「存在一組受控解」與「從原剖框自動找到正確模型」是兩件事。後者還需支持域身分、枚舉覆蓋、候選排序及物理首點驗證。歷史未將這些全部證完，因此保留診斷，未把單／雙／三弧當完整最終自動首點求解器。

公開新主線採工程草稿上的一般線弧與獨立有限距離驗證；這不是宣稱舊多弧模型錯誤，而是交付目標改為工程師可微調草圖。[排序漏選](arc-ordering.md)與[現行範圍](../original-case.md)可交叉閱讀。

原專案曾找到受控多弧正例，仍需另外驗證排程覆蓋、主壁身分和首點。後續工程草稿交付保留診斷用途。

## 現行工程草稿中的角色

多弧模型提供表達能力，也增加候選與可編輯元件。應以主要輪廓和剩餘修改判斷是否值得增加弧數；受控正例仍不等於完整自動搜尋器。 [現行交付判準](../engineering-acceptance.md)。
