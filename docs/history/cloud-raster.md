# 點雲投影柵格與輪廓

**歷史狀態**　部分沿用

## 問題

早期需把散佈點雲轉成可排序的上視輪廓。

## 程式與合成對照

歷史程式用投影柵格、形態學閉合、連通區、外輪廓追蹤、折線簡化與重新取樣。公開反例以一維截線展示閉合如何補掉一個空格，也可能掩蓋真正間隙。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run cloud-raster
```

輸出 `observations` 列出判定依據。 [實作](../../src/Core/Experiments.cs#L216)

## 後續去向

輪廓仍可作上視導引。側壁身份及剖面缺口改由原始 STL 交線另核。沒有足夠紀錄判定這個舊前處理在哪個版本完全停用。

[回方案索引](../engineering-decisions.md)

## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 投影分群可快速取得可視輪廓，適合粗定位及人工審看。 |
| 反例暴露什麼 | 上下蓋或焊道投到同一像素後失去 Z 身分；二維外輪廓不能代替剖框蓋壁。 |
| 後續怎麼處理 | 保留可視化與粗導引；精確來源改由三角面剖切。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 現行工程草稿中的角色

可作快速定位與展示入口，減少找資料的時間；投影失去厚度方向，仍須回原剖框核對蓋壁。工程草稿允許近似，但不把投影輪廓當作已確認去焊道外緣。 [現行交付判準](../engineering-acceptance.md)。
