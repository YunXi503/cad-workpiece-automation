# 閉合導引線雙路徑

**歷史狀態**　部分沿用

## 問題

使用同一對端點建立上視處理範圍時，封閉輪廓的正反走向都能到達終點。

## 程式與合成對照

先分別取正反兩段，再檢查每段能否命中預期側的邊界。合成反例中正向落空、反向命中。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run closed-route
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L21)

## 後續去向

交付流程沿用另一段的試算與確認，人工仍決定實際側別。由端點順序直接決定路線的假設已被取代。

[回方案索引](../engineering-decisions.md)

## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 閉合導引的兩方向路徑可作候選比較。 |
| 反例暴露什麼 | 最短路徑或固定方向未必對應目標分支，需保留起終身分與原序。 |
| 後續怎麼處理 | 保留雙路徑診斷，不把路徑長當物理接受器。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

閉合導引的方向／分支身份會影響最後面的位置。工程近似可接受局部微調，但跨進另一支或選錯整段會增加重畫負擔，不能只挑較短路徑。 [現行交付判準](../engineering-acceptance.md)。
