# 累積弧長等分

**歷史狀態**　正式採用

## 問題

側線原點間距不一，擬合前要建立一致的數值檢查站。

## 程式與合成對照

累加折線邊長，再用站距定位所落原邊並線性內插。示範從不均勻點列得到等長站距及相同首尾。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run arc-length
```

輸出 `observations` 列出判定依據。 [實作](../../src/Core/Experiments.cs#L243)

## 後續去向

原專案保留原始和等分兩套點一起驗證。缺口和獨立分串需先保留，各自等分。

[回方案索引](../engineering-decisions.md)

## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 累積折線長可讓站距不依賴原點密度。 |
| 反例暴露什麼 | 等分得到的點是插值，不能增加掃描觀測；跨缺口先連線會把假邊納入弧長。 |
| 後續怎麼處理 | 現行參考站距、草稿三維等分與 XY 複核都沿用此概念。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 現行工程草稿中的角色

站距統一有助自動處理與結果比較，均分點仍是中間資料。送入 CAD 的元件應看可編輯性與剩餘手調，不必把全部致密點逐一建成草圖元素。 [現行交付判準](../engineering-acceptance.md)。
