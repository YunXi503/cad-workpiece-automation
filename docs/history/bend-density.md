# 彎處加密與站距解耦

**歷史狀態**　部分沿用

## 問題

長弦穿過彎道會漏掉形狀細節。單純提高全部剖框密度則同時增加求交工作。

## 程式與合成對照

範例以弧中點至弦中點的距離作二分條件，另外用固定剖距算站數，兩個輸出各自可核對。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run bend-density
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L32)

## 後續去向

後續流程保留彎處加密和剖框站距分設。實際節省工時與跨工件覆蓋待量測。


## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 彎處加點可增加求交與曲率解析度。 |
| 反例暴露什麼 | 加密後原索引不再對應固定物理站距，不能直接比較第 N 點位置。 |
| 後續怎麼處理 | 顯示密度與弧長參數解耦，保留來源點映射。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 2026-11-08 公開最小重現的實測

**本反例判準**：弦高加密與獨立站距的點數不能直接互換。

| 輸出欄位 | 本次值 |
| --- | --- |
| `chordSpans` | `8` |
| `sectionStations` | `5` |

8個弦跨度與5個剖框站位是不同取樣契約；不能把第幾個點當固定毫米站位。

本輪 `reproduced=true`，表示自製例的預期現象重現；不改變頁首歷史採用狀態，也不等於原公司程式已完整重寫。數值表顯示6位有效數字，完整輸出與數值來源版本見[25方法實跑收據](../evidence/history-replay-20261108.json)；無私有工件輸入。

## 現行工程草稿中的角色

彎處加密是計算取樣策略，不等於 CAD 應保留更多細碎元件。保主要外形與簡化焊道時，須另外評估短段是否增加手調及加工複雜度。 [現行交付判準](../engineering-acceptance.md)。
