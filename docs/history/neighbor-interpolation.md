# 同蓋鄰站推估

**歷史狀態**　部分沿用

## 問題

原始支持缺一站時，可嘗試維持工程草稿的連續性。

## 程式與合成對照

同側前後兩站都有原始觀測並共享蓋身分，才可填一個內插點。更換一側蓋標籤後應維持缺口。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run neighbor-interpolation
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L191)

## 後續去向

原專案允許明示的工程推估。已排除的套筒範圍與來源不明的跨支缺口仍需維持排除或未定。


## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 可靠鄰站可支持可微調工程草稿，避免缺點使整側無法交付。 |
| 反例暴露什麼 | 來源原缺口仍缺；跨實體蓋或支持矛盾不能被插值當成觀測救回。 |
| 後續怎麼處理 | 本次明示工程草稿與端部推估，來源框狀態完整保留。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 2026-11-08 公開最小重現的實測

**本反例判準**：同蓋單缺點轉inferred，異蓋仍保持gap。

| 輸出欄位 | 本次值 |
| --- | --- |
| `sameCover` | `inferred` |
| `differentCover` | `gap` |

推估點不是新增掃描觀測；原缺口與來源ID仍需保留。

本輪 `reproduced=true`，表示自製例的預期現象重現；不改變頁首歷史採用狀態，也不等於原公司程式已完整重寫。數值表顯示6位有效數字，完整輸出與數值來源版本見[25方法實跑收據](../evidence/history-replay-20261108.json)；無私有工件輸入。
