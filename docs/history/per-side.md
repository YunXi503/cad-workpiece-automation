# 逐側判定

**歷史狀態**　僅供診斷

## 問題

剖框全有或全無會讓一側錯支的異常掩蓋另一側可靠支持。

## 程式與合成對照

固定同一組分支與蓋證據，對照成對接受與逐側結果。合成例能保留一側，另一側維持未定。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run per-side
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L146)

## 後續去向

原專案將逐側結果用於異常診斷。要升為工程候選仍需寬蓋與來源支持。


## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 左右側的掃描與焊道不對稱，分別檢查可避免一側拖掉另一側診斷。 |
| 反例暴露什麼 | 一側通過不證另一側同蓋，也不能用單側通過推整框接受。 |
| 後續怎麼處理 | 保留逐側狀態，不自動升級雙側物理接受。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 2026-11-08 公開最小重現的實測

**本反例判準**：耦合策略接受0側，分側策略接受1側。

| 輸出欄位 | 本次值 |
| --- | --- |
| `acceptedCoupled` | `0` |
| `acceptedSeparate` | `1` |

只保留證據足夠的一側；另側未定不能被同時標成通過。

本輪 `reproduced=true`，表示自製例的預期現象重現；不改變頁首歷史採用狀態，也不等於原公司程式已完整重寫。數值表顯示6位有效數字，完整輸出與數值來源版本見[25方法實跑收據](../evidence/history-replay-20261108.json)；無私有工件輸入。

## 現行工程草稿中的角色

局部可靠與未定可分開交代，讓工程師看哪一側已可用、哪一側要修。部分草稿不能被寫成整體數值通過，也不必因一側待修而隱藏其他可審看結果。 [現行交付判準](../engineering-acceptance.md)。
