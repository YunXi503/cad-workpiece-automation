# 軸向區間包絡

**歷史狀態**　待驗證

## 問題

從上視資料抽取各區間的代表邊界，以利產生順序點列。

## 程式與合成對照

公開例按 X 落入區間再取上包絡，清楚暴露同一軸值下有兩支時只保留一支的限制。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run axis-bins
```

輸出 `observations` 列出判定依據。 [實作](../../src/Core/Experiments.cs#L225)

## 後續去向

早期區間程式保留於歷史基線。後續處理引入分支與順序核對，這個舊入口何時完全停用，現有紀錄未確認。


## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 輪廓對某座標軸為單值時，區間極值可快速排序。 |
| 反例暴露什麼 | 同一 X 同時有兩支時包絡只保留一支，轉向與末端也可能被合併。 |
| 後續怎麼處理 | 區間代表點保留歷史；完整停用時間未確認。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 2026-11-08 公開最小重現的實測

**本反例判準**：6點變3個上包絡區間，不能保留較低分支。

| 輸出欄位 | 本次值 |
| --- | --- |
| `points` | `6` |
| `bins` | `3` |
| `lowerBranchRetained` | `False` |

lowerBranchRetained=False是預期暴露的失效；reproduced=True不表示區間法成為最終採用。

本輪 `reproduced=true`，表示自製例的預期現象重現；不改變頁首歷史採用狀態，也不等於原公司程式已完整重寫。數值表顯示6位有效數字，完整輸出與數值來源版本見[25方法實跑收據](../evidence/history-replay-20261108.json)；無私有工件輸入。

## 現行工程草稿中的角色
