# 短窗直度與固定方向

**歷史狀態**　僅供診斷

## 問題

從原序點列找焊道圓角後第一個側壁原點。

## 程式與合成對照

自由方向直線能完全通過斜短窗。固定壁方向可拒絕這個例子，但遠處平行窗口仍有零直度殘差。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run short-window
```

輸出 `observations` 列出判定依據，`reproduced` 表示合成對照是否符合預期。 [實作](../../src/Core/Experiments.cs#L62)

## 為什麼小殘差沒有證明選對

設計假設是「圓角結束後，側壁應可在短窗內近似直線」。它只給必要線索：圓角內局部、遠處平行面、焊道一側也可能在短窗內很直。固定方向可排除斜窗，仍無法區分兩個位置不同但方向相同的窗。

反例保留同一點距門檻，移到錯誤平行窗仍通過，因此拒絕把直度當物理身分接受器。帶寬、方向、位置、原面身分分開列證，不能再調窗長讓指定框看起來過關。原件 F75 的支持位置圖提供此問題的實際脈絡。[原件剖框](../original-case.md#來源與未定狀態)

原專案固定方向後仍有窗落在圓角內。直度與帶寬保留作診斷，物理首點仍需來源位置證據。

## 現行工程草稿中的角色

直度可提示候選，不必等精確圓角首點證明才提供近似草稿。仍要看位置是否正確，避免把短而直但錯位的片段交給工程師整段修回。 [現行交付判準](../engineering-acceptance.md)。
