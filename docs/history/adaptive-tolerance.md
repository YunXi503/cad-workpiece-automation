# 自動草稿公差與段數

**歷史狀態**　正式採用

## 問題

固定單一容許值時，不同尺度或彎度可能得到太多元件。

## 程式與合成對照

公開例用固定候選表表達在公差內挑較少元件的決策，逐項比較實際誤差。歷史介面另顯示各側公差、XY 誤差與半徑。

```shell
dotnet src/Cli/bin/Release/net10.0/Cli.dll experiment run adaptive-tolerance
```

輸出 `observations` 列出判定依據。 [實作](../../src/Core/Experiments.cs#L252)

## 後續去向

用於工程草稿順化。工程公差、取整位移上界及實際接觸驗收各有判準。


## 設計假設、失效條件與留下的技術

| 問題 | 設計判斷 |
| --- | --- |
| 什麼條件下有效 | 工程順化可用誤差與段數候選表讓操作者看取捨。 |
| 反例暴露什麼 | 放寬門檻後段數下降不能算同判準改善；歷史工程接受與製造驗收不同。 |
| 後續怎麼處理 | 現行原件固定 0.3 mm 擬合、0.05 mm 取整位移，不自動調寬。 |

以上是歷史方法的適用邊界與現行去向。此頁命令實跑獨立最小反例，原公司程式與原資料留本機；缺少紀錄的淘汰原因不補推測。

## 2026-11-08 公開最小重現的實測

**本反例判準**：固定候選在0.1／0.2／0.3門檻分別選7／5／5段。

| 輸出欄位 | 本次值 |
| --- | --- |
| `strictCount` | `7` |
| `draftCount` | `5` |
| `limitPointThreeCount` | `5` |

這是列舉好的3個段數／誤差候選之選擇示意，不是實際重擬合器；0.32誤差的3段方案不被0.3接受。

本輪 `reproduced=true`，表示自製例的預期現象重現；不改變頁首歷史採用狀態，也不等於原公司程式已完整重寫。數值表顯示6位有效數字，完整輸出與數值來源版本見[25方法實跑收據](../evidence/history-replay-20261108.json)；無私有工件輸入。

## 現行工程草稿中的角色

2026-11-06 再確認以可用外形、少手調與省工為重點，0.3 mm 作本版數值設定與診斷。工程候選可依用途比較，但本輪未改算法公差，也不把調寬後的數字冒充同條件改善。 [現行交付判準](../engineering-acceptance.md)。
